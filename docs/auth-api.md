# 회원가입 · 로그인 API

프론트의 회원가입(`#/signup`)과 로그인(`#/login`) 화면이 부르는 API입니다.
타입 정의는 `src/types/neareast.ts`의 `SignupRequest`, `LoginRequest`, `AuthUser`이고, 호출 코드는 `src/api/auth.ts`입니다.

모든 요청은 `{VITE_API_BASE_URL}` 아래로 가고, 본문은 JSON입니다.

---

## 회원가입 `POST /auth/signup`

```json
{ "email": "you@example.com", "password": "abcd1234", "nickname": "동해여행자" }
```

프론트에서 미리 확인하는 조건은 아래와 같습니다. 서버에서도 같은 조건을 다시 확인해 주세요.
- 이메일 형식
- 닉네임 2~12자
- 비밀번호 8자 이상, 영문과 숫자 포함

| 응답 | 의미 | 프론트 표시 |
|------|------|-------------|
| `200` / `201` + `AuthUser` | 가입 완료, **로그인된 상태로** 응답 | 바로 로그인 처리 후 메인으로 이동 |
| `409` | 이미 가입된 이메일 | "이미 가입된 이메일이에요. 로그인해 주세요." |
| `400` | 입력값 오류 | "입력한 내용을 다시 확인해 주세요." |
| 그 외 | | "가입하지 못했어요. 잠시 후 다시 시도해 주세요." |

## 로그인 `POST /auth/login`

```json
{ "email": "you@example.com", "password": "abcd1234" }
```

| 응답 | 의미 | 프론트 표시 |
|------|------|-------------|
| `200` + `AuthUser` | 로그인 성공 | 메인으로 이동, 헤더에 "닉네임님 · 로그아웃" |
| `400` / `401` | 이메일·비밀번호 불일치 | "이메일 또는 비밀번호를 확인해 주세요." |
| 그 외 | | "로그인하지 못했어요. 잠시 후 다시 시도해 주세요." |

보안을 위해, 이메일이 없는 경우와 비밀번호가 틀린 경우를 **같은 응답(401)** 으로 보내 주세요.

## 로그아웃 `POST /auth/logout`

본문은 `{}`이고, `204`로 응답합니다. 실패해도 프론트는 로그아웃 상태로 바꿉니다.

## 마이페이지

로그인한 사용자 본인에 대한 요청입니다. 로그인하지 않았으면 `401`로 응답해 주세요.
호출 코드는 `src/api/account.ts`입니다.

| 기능 | 요청 | 본문 | 성공 응답 |
|------|------|------|-----------|
| 닉네임 변경 | `PATCH /users/me` | `{ "nickname": "새닉네임" }` (2~12자) | `200` + 바뀐 `AuthUser` |
| 비밀번호 변경 | `PUT /users/me/password` | `{ "currentPassword": "…", "newPassword": "…" }` | `204` |
| 회원 탈퇴 | `DELETE /users/me` | 없음 | `204` (세션도 끝내 주세요) |

- 비밀번호 변경에서 현재 비밀번호가 틀리면 `400`, `401`, `403` 중 하나로 응답해 주세요. 프론트는 셋 다 "현재 비밀번호가 맞지 않아요."로 표시합니다.
- 새 비밀번호 규칙은 회원가입과 같습니다. 프론트 규칙은 `src/utils/validation.ts`에 있습니다.
- 그 밖의 실패에는 "잠시 후 다시 시도해 주세요." 문구가 표시됩니다.

## 로그인 유지 방식 (백엔드와 정할 것)

- 프론트는 화면 표시용으로 `AuthUser`(이메일·닉네임)만 브라우저에 저장합니다. **비밀번호와 토큰은 저장하지 않습니다.**
- 권장 방식은 서버가 **HttpOnly 쿠키**로 세션을 주는 것입니다. 그러면 프론트 코드가 토큰을 다룰 필요가 없습니다.
  - 이 경우 `src/api/client.ts`의 `fetch`에 `credentials: 'include'`를 추가해야 합니다.
  - 백엔드 CORS에서 `http://localhost:5173`에 대해 `Access-Control-Allow-Credentials: true`를 허용해야 합니다.
- 토큰(JWT)을 본문으로 주는 방식으로 정하면 프론트 저장 위치와 헤더 처리를 같이 정해야 합니다.
- 새로고침 후 로그인이 유효한지 확인할 `GET /auth/me`가 있으면 좋습니다. 지금 프론트는 저장해 둔 사용자 정보를 그대로 믿습니다.

## 프론트에서 연결하는 방법

지금은 데모 인증(`src/api/mockAuth.ts`)으로 동작합니다. 데모 인증은 가입한 이메일인지만 확인하고, 비밀번호는 확인하지도 저장하지도 않습니다.
API가 준비되면 프론트 `.env`에 아래를 넣고 개발 서버를 다시 켭니다.

```
VITE_USE_MOCK_AUTH=false
```
