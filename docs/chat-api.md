# AI 여행 플래너 채팅 API (`POST /chat`)

프론트의 **AI 여행 플래너** 화면이 사용자가 보낸 모든 메시지를 이 API로 보냅니다.
챗봇은 두 가지 일을 함께 합니다.

1. **자유 질문에 답하기**: "동해시 원목 신호등 보고 싶은데 어딨어?"처럼 역이나 장소를 물으면 답하고, 관련 장소 카드를 붙입니다.
2. **여행 일정 짜기**: 대화에서 여행 조건 5가지를 알아내서 채우고, 빠진 조건을 이어서 묻습니다.

프론트 타입 정의는 `src/types/neareast.ts`의 `ChatRequest`, `ChatResponse`, `ChatPlace`입니다.
이 문서와 타입이 다르면 타입이 기준입니다.

---

## 요청

`POST {VITE_API_BASE_URL}/chat`
`Content-Type: application/json`

```json
{
  "messages": [
    { "role": "assistant", "text": "언제 떠나실 건가요?" },
    { "role": "user", "text": "이번 주 주말" },
    { "role": "assistant", "text": "좋아요! 여행 시간은 어느 정도로 생각하세요?" },
    { "role": "user", "text": "나 동해시 원목 신호등을 보고 싶은데 어딨어?" }
  ],
  "conditions": {
    "travelDate": "이번 주 주말"
  },
  "savedPlaces": [
    { "id": "station-묵호역", "name": "묵호역", "category": "역", "stationName": "묵호역", "description": "…" }
  ]
}
```

| 필드 | 설명 |
|------|------|
| `messages` | 지금까지의 대화 전체입니다. 시간 순서대로 들어 있고, **마지막 항목이 방금 사용자가 보낸 메시지**입니다. 서버는 대화를 저장하지 않아도 됩니다. |
| `messages[].role` | `"user"` 또는 `"assistant"` |
| `conditions` | 지금까지 채워진 여행 조건입니다. 아직 모르는 조건은 키가 아예 없습니다. |
| `savedPlaces` | 사용자가 "여행에 담기"로 담아둔 장소입니다. 형식은 응답의 `places[]`와 같습니다. 일정을 짤 때 이 장소들을 방문 후보로 넣어 주세요. 없으면 `[]`입니다. |

### 여행 조건 키

| 키 | 화면 이름 | 값 예시 |
|----|-----------|---------|
| `travelDate` | 여행 날짜 | `"이번 주 주말"`, `"11월 28일 토요일"` |
| `travelDuration` | 여행 시간 | `"반나절 (약 4시간)"`, `"하루 (약 8시간)"`, `"1박 2일"` |
| `departureStation` | 출발지 | `"묵호역"` (역 이름은 `○○역` 형태) |
| `arrivalStation` | 도착지 | `"동해역"` |
| `requiredStop` | 중간 방문역 | `"추암역"`, 들를 곳이 없으면 `"없어요"` |

값은 화면에 그대로 표시되는 문자열입니다.

## 응답

`200 OK`

```json
{
  "reply": "동해시에서 찾아본 결과를 알려드릴게요. …",
  "places": [
    {
      "id": "place-123",
      "name": "○○",
      "category": "관광지",
      "stationName": "묵호역",
      "description": "추천 이유나 한 줄 설명",
      "notice": "선로 접근 금지 · 지정된 장소에서만 촬영",
      "source": "공공데이터 관광 정보"
    }
  ],
  "conditionUpdates": {
    "travelDuration": "하루 (약 8시간)"
  },
  "quickReplies": ["반나절 (약 4시간)", "하루 (약 8시간)", "1박 2일"]
}
```

| 필드 | 필수 | 설명 |
|------|------|------|
| `reply` | ✓ | 말풍선에 표시할 답변입니다. `\n` 줄바꿈이 그대로 표시됩니다. |
| `places` | | 답변 아래에 붙는 장소 카드입니다. 장소를 추천하지 않으면 빼거나 `[]`로 보냅니다. |
| `places[].id` | ✓ | 장소의 고유 ID입니다. 같은 장소는 항상 같은 ID여야 "플래너에 담기"가 중복되지 않습니다. |
| `places[].name`, `category`, `description` | ✓ | 카드의 이름, 분류 배지, 설명 |
| `places[].stationName` | | 가장 가까운 역 |
| `places[].notice` | | 빨간 경고 박스로 표시됩니다. 안전 수칙이나 확인이 필요한 정보를 넣습니다. |
| `places[].source` | | 데이터 출처입니다. 카드 아래에 작게 표시됩니다. |
| `conditionUpdates` | | 이번 메시지로 새로 알게 되거나 바뀐 여행 조건입니다. 프론트가 기존 `conditions`에 덮어씁니다. |
| `quickReplies` | | 답변 아래 빠른 답변 버튼입니다. 누르면 그 문자열이 사용자 메시지로 전송됩니다. 조건 5개가 모두 채워졌으면 `"일정 만들기 →"`를 넣어 주세요. 이 버튼만은 프론트가 직접 처리해서 일정 비교 화면으로 넘어갑니다. |

### 오류

`200`이 아닌 응답이 오면 프론트는 "답변을 받지 못했어요. 잠시 후 다시 보내 주세요."를 표시합니다.
본문 형식은 따로 정하지 않았습니다.

## 챗봇이 지켜야 할 동작

1. **데이터에 있는 것만 답합니다.** 역·장소 정보는 백엔드가 가진 데이터(공공데이터, 팀 수집 데이터)에서만 가져옵니다. 데이터에 없으면 "아직 정보가 없다"고 답하고 `places`는 비웁니다. 없는 장소를 지어내면 사용자가 실제로 찾아갔다가 헛걸음하게 됩니다.
2. **질문에 답한 뒤 일정 짜기로 돌아옵니다.** 빠진 여행 조건이 있으면 답변 끝에 다음 조건을 묻고, 그 선택지를 `quickReplies`로 줍니다. 묻는 순서는 위 표의 순서입니다.
3. **한 문장에서 여러 조건을 뽑습니다.** "토요일에 묵호역에서 출발해서 추암 들렀다 동해역으로 와"라는 메시지에는 `travelDate`, `departureStation`, `requiredStop`, `arrivalStation`을 한 번에 `conditionUpdates`로 보냅니다.
4. **사용자가 조건을 바꾸면 덮어씁니다.** "출발은 강릉역으로 바꿀래"에는 `conditionUpdates: { "departureStation": "강릉역" }`을 보냅니다.

## 프론트에서 연결하는 방법

지금 프론트는 이 API 대신 같은 형식으로 답하는 데모 응답(`src/api/mockChat.ts`)을 씁니다.
API가 준비되면 프론트 `.env`에 아래처럼 넣고 개발 서버를 다시 켭니다.

```
VITE_API_BASE_URL=http://localhost:8080/api
VITE_USE_MOCK_CHAT=false
```

개발 중에는 프론트가 `http://localhost:5173`에서 열리므로, 백엔드에서 이 주소의 CORS를 허용해 주세요.

## 참고: AI 모델 연결 시

- **AI API 키는 백엔드에만 둡니다.** 프론트 코드에 넣으면 브라우저에서 누구나 볼 수 있습니다.
- 응답이 위 JSON 형식을 항상 지키도록 모델의 **구조화된 출력(JSON 스키마 지정)** 기능을 쓰는 것을 권장합니다. Claude를 쓴다면 Messages API의 `output_config.format`에 이 응답 형식의 JSON 스키마를 넣으면 됩니다. 별도 요청이 없으면 모델은 `claude-opus-5-5`를 기본으로 하세요.
- 장소 데이터는 모델에 요청과 함께 넣거나 도구(tool)로 조회하게 해서, 모델이 데이터 밖의 장소를 만들지 않도록 시스템 프롬프트에 위 "챗봇이 지켜야 할 동작"을 적어 주세요.
